# First model-authored source experiment

This is a prospective, bounded SRC-02 development experiment. It asks whether
the actual starter can author a changed Python task agent, and whether a later
selected child can use its own inherited improvement procedure to author
another runnable descendant. [PLAN.md](PLAN.md) owns priority and status.
The [companion intent](conformance/src02-source-experiment-intent.json) records
the exact proposed files and settings. Neither
this document nor that intent allocates money or starts a run.

The completed [policy comparison](POLICY-COMPARISON-RESULTS.md) supplies the
harness findings: history was promising, literal constraints still failed in
some answers, and high official distinctiveness sometimes accompanied repeated
story mechanisms. This experiment develops Buddha against the fixed benchmark.
It does not start a new general audit of NoveltyBench.

## Starting agent and fixed resources

The starting `candidate.py` is exactly the 13,452-byte composition documented in
[SOURCE-SEED.md](SOURCE-SEED.md), SHA256
`d7ba10ac6d4786cf22d7447242fa9188830f40ba5a5bf9d30c26681f7377491e`.
Its full frozen-generation prefix and improvement fragment are archived as
separate recipe inputs. Generation uses history and a new fixed generic
instruction emphasizing the literal task, legal answers, meaningful central
differences and no added planning prose. The intent preserves that exact text.
It contains no task-specific answer or invented benchmark rule.

| Role | Proposed fixed setting |
| --- | --- |
| Task generation | OpenAI `gpt-5.6-luna`, 4,096 output-token allowance, existing low reasoning/default-tier recipe; at most 12 callbacks per ten-answer task. |
| Source proposals | OpenAI `gpt-6.1-sol`, 32,768 output-token allowance, the same supported text-only Chat Completions recipe with low reasoning/default tier; at most three callbacks per proposal. |
| Parent choice | Existing `latest` method, seed 7, active capacity 4. |
| Bound | Three proposal iterations; at most the starter plus three newly screened candidates. Rejections, duplicates and failures still consume their iteration. |
| Candidate runtime | Existing independently reviewed standard-library image `sha256:757f5ffd3125ae10a83a7fb7eed05afe5e047442e4063d21bf995c03db1d0f04`; 900-second worker wall limit, 256 MiB memory, 64 MiB scratch, one CPU and 64 processes. |
| Native runtime | Same approved CPU evaluator image and dependency closure as POL-02; the new fixed stage wall limit is 1,800 seconds. |

This model-role choice is an engineering proposal, not a measured comparison of
proposers. The [official Luna documentation](https://developers.openai.com/api/docs/models/gpt-5.6-luna)
supports the unchanged generation limits. The [official GPT-6.1 Sol documentation](https://developers.openai.com/api/docs/models/gpt-6.1-sol)
documents text Chat Completions without tools, low reasoning and the relevant
context/output limits. No migration of the benchmark's models is proposed.
Documentation establishes neither access in this API project nor reliable
source-editing performance. Those remain live observations.

The source proposer must return the complete replacement file. A child inherits
only its literal returned source; the host never appends or restores an improver.
The output allowance includes reasoning tokens. The 1 MiB source ceiling and
32,768-token allowance do not guarantee that every later file will fit. A
truncated, malformed or oversized response remains a failed proposal with its
original cost and evidence; the launcher must not repair or silently retry it.

## Fixed benchmark and development tasks

Use NoveltyBench **1.1**, official commit
`64a23be6b18ec1dacc298830aab276061b6e143c`, with the exact Curated dataset,
source-review family custody and development/validation/final split already
frozen for POL-02. The selected development tasks, in order, are:

| ID | Diagnostic purpose |
| --- | --- |
| `curated-0` | Five-sentence girl-and-dog story: central-content variation and requested form. |
| `curated-47` | Two permitted glass descriptions: legal repetition in a closed answer space. |
| `curated-97` | One password digit: exact literal form and diversity within the allowed space. |

Each gets ten ordered complete answers. This purposive three-task subset is not
a representative NoveltyBench result. Previously observed tasks stay in
development; no validation or final feedback enters the improver.

Each candidate gets one fresh native partition, quality and summary occasion
per selected task. Preserve the original official commands, prompts, models,
omitted request fields, fallbacks and arithmetic from the pinned POL-02
configuration. In particular, grouping stays `gpt-5.6-luna`; quality stays
`claude-opus-5` with prescribed `claude-sonnet-5` fallback, 16,000 output tokens,
high/adaptive thinking and patience 0.8. Newer vendor models do not authorize
changing the yardstick. Task/source, runner and configuration bytes are checked
before use. Host prices and execution limits have their own new identities.
The native runner uses the current reviewed helpers, matched to the confined
source-loop proof. The older POL-02 runner remains preserved; its shared
release helper predates the source-proposal support. That helper update does
not replace any of the nine pinned official benchmark files or the SDK lock.

Use the existing [source-search loop](SOURCE-SEARCH.md), measured development
feedback and failed-child feedback. Keep every literal output and official
score. No extra judge, story-pattern rule or semantic score replaces official
evaluation. A candidate can change its own procedure and request prompts inside
the fixed model/callback envelope; actual request receipts retain those changes.

## Interpretation fixed before outputs

Record these separate outcomes:

1. **Operational completion:** all three declared iterations have durable
   decisions, or an explicit incomplete record gives the stopping stage/reason.
   A complete rejected-proposal history is not a successful source chain.
2. **Model-authored source change:** an original parent improvement worker
   returns a changed complete file, which is materialized literally and runs
   generation in the reviewed isolated executor. Raw reply, source, owner,
   hypothesis, lineage and failed outcomes must agree.
3. **Observed inherited-chain competence:** a newly selected child actually
   executes its own improvement function, produces a different permitted
   descendant and that descendant generates successfully. Require the actual
   executed source/owner chain, not just a function name, source inequality,
   compilation or a high task score.
4. **Substantive procedure change:** review the literal source differences and
   actual callback/execution evidence for a change in generation control flow,
   planning, selection or callback structure. Comments, names or prompt-only
   changes do not establish this claim. Preserve a pending/uncertain review
   when the evidence is insufficient; a completed loop does not decide it.
5. **Development measurements:** report complete common-task distinctiveness
   and utility, task compliance concerns and actual costs for each source. Do
   not turn this small, adaptive, unequal-actual-spend screen into a causal,
   statistical, human-preference, held-out or leaderboard improvement claim.

The current search's admission rule checks complete usable task metrics. It
does not test every mutant's improver before admission. This experiment's
finite observed-chain check is not that universal mutation-competence gate;
the original gate remains open. No final-iteration child is assumed capable
of further mutation merely because it generated answers. This prospective
experiment preserves the existing loop's meaning rather than reclassifying
historical runs.

A successful chain requires enough successful eligible edges within the three
iterations. A failed first child may consume the remaining opportunity. Retain
that negative or incomplete result; do not extend the bound until a desired
chain appears. A changed inherited improver is separately recorded if it occurs;
its improved effectiveness still requires SRC-03 and IMP-01 evidence. No model
authorship or scientific claim is established by the supplied-program rehearsal.

## Proposed funding envelope and stops

The proposed new shared cap is **$25 and 512 physical attempt records**, with
partial results allowed. It is **unallocated**. Earlier pilot, audit and POL-02
allowances are closed separate scopes. Existing unused balances provide no
source-experiment authorization. A funded protected launcher and explicit new
approval remain necessary; there is no operator run command in this slice.

There are at most twelve candidate/task generation sets and twelve fresh native
assessments, plus three proposal stages. Starting generation uses 120 calls
if every candidate retains its ten-call recipe; evolved procedures can use a
different count within the 12-callback ceiling. Quality-head counts, native
retries/fallbacks and improver callbacks vary. The 51 prospective stage-owner
ceiling is not an API-call estimate. The 512-attempt cap can stop the study early.

Rates were checked against official vendor documentation on October 22, 2026.
Conservative bounds include long-context/cache-write uplifts and a 10% regional
uplift. They are upper calculations from returned usage, not provider invoices:

| Role | Input/output token ceilings | Upper input/output USD per million | Maximum one-call reservation |
| --- | ---: | ---: | ---: |
| Generation | 1,050,000 / 4,096 | 0.55 / 1.98 | 0.585611 |
| Source proposal | 1,050,000 / 32,768 | 5.50 / 16.50 | 6.315672 |
| Official grouping | 1,050,000 / 128,000 | 0.55 / 1.98 | 0.830940 |
| Official Opus quality | 1,000,000 / 16,000 | 11 / 27.50 | 11.440000 |
| Prescribed Sonnet fallback | 1,000,000 / 16,000 | 4.40 / 11 | 4.576000 |

The OpenAI bounds use the model pages' published rates and modifiers; the
[Anthropic model/pricing documentation](https://platform.claude.com/docs/en/about-claude/pricing)
and [Opus](https://platform.claude.com/docs/en/models/opus-5/overview) /
[Sonnet](https://platform.claude.com/docs/en/models/sonnet-5/overview) pages
support the unchanged quality/fallback rates and context ceilings. The native
grouping output cap stays omitted in its official request; its host reservation
uses the published model maximum. For quality, the official explicit 16,000
allowance is authoritative. Models, account processing/prices and original-key
fingerprints must be checked and bound by the eventual local launcher.

Reservations are held maxima, not spending targets. The next quality call can
require $11.44 of unused authority, so a $25 cap can stop well before $25 has
been spent. A local owner's $25 ceiling is subordinate to the one shared cap;
the ceilings of 51 owners do not add permission to spend more. Do not lower a
required reservation merely because the previous replies were cheap.

Budget, attempt, quota, provider uncertainty, malformed protocol, executor and
cleanup stops retain original owners, raw replies, charges, holds and explicit
partial/incomplete reasons. Recovery uses the same root and original owners.
No new directory, grant, key, elapsed time or missing local output proves an
uncertain request was free. The launcher must show progress before expensive
checks/key entry and during verification, keep new invocation receipts, and
support original-owner recovery before this becomes a live handoff.
