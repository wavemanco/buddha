# BENCH-02C3B: dependency security and license review

Reviewed October 20, 2026. This is an independent review of the prepared artifacts and the selected official execution path. It does not change the benchmark, approve a paid run, certify every dependency, or replace the living [PLAN](../PLAN.md).

## Decision and exact scope

**Keep the original CUDA closure as inspected evidence; do not install or execute it for this CPU-only project profile.** The actual CUDA, cuDNN and cuSPARSELt notices impose an NVIDIA-GPU purpose restriction. Local research alone does not resolve that restriction. The root implementation owner accepted this hold and selected investigation of an explicitly separate official CPU Torch build instead. That variant requires its own artifact identity, license review, installation proof and native differential evidence; it cannot be called the exact upstream binary lock.

The source under review is NoveltyBench commit `64a23be6b18ec1dacc298830aab276061b6e143c`, specifically the unchanged full `src.partition` entry point with the owner-frozen arguments `--version 1.1 --alg llm`, followed by official scoring/summary. Inputs are bounded generations JSONL and declared native cache artifacts. The profile excludes model weights, checkpoint loading, local neural inference/training, starting Torch RPC/distributed sessions or sending RPCs, remote-code loading, NLTK corpora/downloads and arbitrary executable agents. These exclusions are part of the capability boundary, not claims that the installed libraries lack those features or avoid importing their definitions.

Retaining vulnerable versions for this narrow, confined offline compatibility experiment is a documented research exception. It is not a production dependency recommendation or a clean vulnerability-audit result. The existing C3A environment and its separately declared AnyIO `4.14.2` security overlay remain unchanged. No Torch or Transformers major upgrade is silently substituted.

## What the official path actually uses

The complete official `src/partition.py` was read. Its top level imports Torch, Transformers, SacreBLEU and ROUGE and calls `torch.cuda.is_available()`. Therefore these libraries are not absent merely because the selected algorithm is LLM-based. `rouge_score` also imports NLTK eagerly; its default tokenizer constructs no Porter stemmer when `use_stemmer=False`.

For the frozen LLM route, the algorithm calls `partition_llm`, then official `run_stage` and the judge SDK. The native parser/fold/repair/cache operations remain official. The inspected route does not call `torch.load`, `from_pretrained`, FSSpec reference filesystems, NLTK resource loaders, model conversion or training. Alternative `bertscore` and `classifier` paths explicitly load external model assets; they are outside this profile. This is source-level applicability evidence. Use a finite offline container build with an explicitly inventoried toolchain, no secrets, no home/docker-socket/GPU exposure and no package-index access. Hash the built wheel and final installed inventory/image. Any undeclared build dependency is an explicit new artifact, not an online resolver escape.
3. **Actual entrypoint proof:** import the unchanged full partition module in the final image; bind all real file origins and explicitly reviewed synthetic module loaders. Do not hide missing imports behind stubs, omit imported files or delete source algorithms. Verify import-time cache/write behavior and that private caches cannot mutate selected host files. Retain the bytecode-prefix/source-identity guards from C3A.
4. **Fail-closed capability profile:** owner-frozen LLM arguments, selected JSONL/cache paths and evaluator role only; reject changed command/module, algorithms or model/resource input paths before paid dispatch. No weights, pickle/PT2/JAR/XML/corpora/FSSpec-reference inputs, arbitrary package installs, raw provider credentials or external worker network. Do not repurpose this image for arbitrary evolved agent execution.
5. **Measured conformance and failure behavior:** real Docker network/readonly/resource/cleanup denials remain in force. Run the unchanged full partition entry point against direct and funded mocked SDK responses, including native fold/repair/refusal/fallback/retry and partial-cache recovery. Preserve every physical attempt in the host ledger; unknown liability stops SDK retries. Evidence establishes this declared CPU profile only, not equivalence with all hardware/backends or an unknown future release.

Security controls reduce the reachable operations and blast radius; they do not repair old packages, prove absence of native vulnerabilities, attest an untrusted Docker daemon, or establish a universal container-escape boundary. There is no live authorization, model call or readiness claim in this review.

## Reviewed offline ROUGE build shape

The environment owner proposed using the **existing actual Executor and immutable C3A image**, rather than installing or executing source on the host. The read-only `/runner` mount contains a tiny reviewed build worker and channel helper; `/inputs` contains only the verified ROUGE source, Setuptools `79.0.1` wheel and hashed builder requirements. The actual source archive has **26 members, 75,835 declared uncompressed file bytes**, one `rouge_score-0.1.2` root and only regular files/directories.
