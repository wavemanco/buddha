# Publishing a development screen

Proposed design for the live comparison. [PLAN.md](PLAN.md) tracks the next step. A screen report gives the archive the task scores, candidate disposition, provenance and accounting. It should describe the same work the runner accepted, including a fully accounted candidate failure when there is one.

V3 stopped inside the collector's final directory comparison, before the last preflight. Its byte and SQLite checks had passed. The diagnostic cannot tell us which entry or field differed. A later read-only reconstruction passed. The [stop record](conformance/d8-v3-screen-publication-stop.json) preserves that distinction. Removing the repeated preflight alone would leave the observed stop in place.

## What the eight checks earn

| Current check, in order | Wrong report it can prevent that another check misses | Decision |
| --- | --- | --- |
| 1. After the task loop, reread each returned child report. | A different, internally valid child report could be substituted after the runner accepted the original. A collector that derives its expected digest from the file it opens can accept the replacement. | Keep the existing immediate return-to-file check. Pass those original digests into the collector's first report reads, including the v2 disposition scan. Match consumed reports to the accepted set. Delete the post-loop sweep. |
| 2. List the screen tree before reading. | Reading files by name could silently miss an extra task, owner, seal or sealed output. | Keep the initial names and types needed by the existing schedule and inventory checks. |
| 3. Reconstruct the report from saved evidence. | A complete-looking report could mix tasks, answers, judges, output rows or spending across owners, or assign a score to a failed candidate. | Keep the collector, official metric projection and ledger reconciliation. Bind them to the original active screen and review. |
| 4. Reread consumed files and check SQLite sidecars. | Bytes could change after a first read, or a journal could make the database file an incomplete view of spending. | Keep one final byte-and-sidecar check for each dependency. Remove a nested finish only when its distinct receipts, locks, namespaces and sidecars reach the same final check. |
| 5. List the screen tree again and compare metadata. | A new owner or seal could appear after the first listing. An earlier validated file or directory could be replaced. A directory clock change alone cannot change the report. | Keep the last check of relevant names, types and identities and stability of protected files. Ignore directory timestamps and directory sizes. Use no retry. |
| 6. Recheck external native staging. | An added input could escape a check of the screen directory. The native evaluator mounts a separate directory. | Keep the exact input membership and types on the selected shallow staging mounts, and verify the staged bytes against their pins. Use the same directory identity rule there. |
| 7. Run preflight again before writing. | The collector alone can currently accept a bare evaluation directory after a terminal generation failure or miss an exact descriptor binding on a later native owner. The rest repeats execution and completion checks or validates the current installation after execution has finished. | Keep preflight before dispatch. Put the unique report checks into active collection, then delete the second preflight. Validate every original invocation binding from the manifests. Read its bytes again only when publication or the next decision depends on them. |
| 8. Write the report or verify an existing one. | A rerun could overwrite or return a different report, or replace its stored accounting with today's totals. | Keep exclusive creation and fsync. For an existing report, check its stored result and compatible historical accounting inside the same observation and return it unchanged. |

## Proposed active path

**Keep the identity the runner accepted.** Under the existing trial lease and screen lock, use the in-memory screen, review and input pins already obtained at preflight. The accepted child digest must be supplied at first read and apply to both generated and settled-failure reports. Check that the collector used exactly the reports accepted by the runner. A failed generation may end the ordered task prefix, with its generation owner and seal, no evaluation path even if empty, and no later task. A fully accounted candidate failure remains a recorded outcome. Whether that outcome is sufficient to advance depends on the screen's role under the existing scientific rules.

**Validate the report once from its evidence.** Reuse the task schedule, recipe builders, completion inventories, owner manifests and ledger mirror. Require byte-exact task, descriptor and context files and the original review and invocation pins for each owner, including later native stages. Check actual bytes for the inputs this publication uses, including the host scoring projector and lineage, and the fixed trial controls that still govern the decision. Match their original pins and reuse receipts by path and digest. For an invocation input used solely at dispatch, the manifest and seal record its historical digest. A change to that file after the last child seals is relevant before another dispatch using it, but cannot change the completed result. Preserve the existing per-input bounds and capture limits. Reject conflicting pins for the same path within the original active schedule. Keep case-fold alias checks in the namespaces used for custody, including empty directories where the sealed inventory already rejects aliases. Use the original trial controls returned by the writer lease, including the funding definition and marker. Use the collector's validated owner IDs and captured authority for settlement, completion anchors and any existing-report check. Keep runtime, selected evaluator, profile and other dispatch-only byte checks before work that uses those inputs. Published provenance records the original manifest pins. It makes no claim that every historical executable or caller-supplied dispatch file still has those bytes on disk.

**Close the read before returning or writing.** The opening and closing checks cover the namespaces whose membership the validator uses: task, owner and completion schedules, sealed output inventories, selected staging, lock and database neighbors, and required absences such as an evaluation after a failed generation. Reuse the existing enumerations and manifest-derived paths. An unrelated file outside those checks or the consumed paths earns no veto. Check root identities as well as entries, rejecting links, reparse points and aliases at protected paths. A protected directory is identified by its path, type, device and inode. Retain stable bounded reads for regular files and compare their signatures after their final hash, including consumed external controls and the authority database. Retain the SQLite sidecar checks around the final byte pass. This detects changes at the observation boundaries. The lease coordinates Buddha writers and provides no atomic snapshot against an outside process.

**Keep the ownership and write boundary intact.** The scoped trial lease already binds a lock identity. The current screen lock only stores a PID and unlinks the path on exit. Retain its identity from acquisition, check it before the report is returned or created, and remove only the lock the writer owns. Use the existing lock helper. If an existing report was observed, read and validate it against the same captured result and authority before finalizing. Require canonical bytes on the scoped path, as the immediately following study reader already does, and preserve the stored compatible accounting snapshot. The standalone legacy writer can still return semantically equivalent JSON encodings. If an unexpected report arrives afterward, exclusive creation refuses it without reopening the ledger. Passive inspection keeps its current canonical-report rules. Compatibility verifies the sealed result and that owner's accounting. It cannot authenticate an earlier aggregate snapshot for unrelated owners. When an independent expected report digest already exists, keep checking it. Carry the returned report's canonical digest in memory into the immediate study read. Its provenance reference should identify the publication the runner returned, even if a different compatible report appears at the same path. Later independent inspection uses the caller's existing expected digest or the established compatibility rules. No new saved checkpoint.

**Apply one directory rule through the study's next read.** The study immediately reads the completed screen again before advancing. Its nested screen collector, outer capture, tree registry and write-scope comparison also compare directory metadata. Use the same directory identity rule along this active writer path. Reuse the existing scoped lease context and census helpers. Preserve names, types, file signatures and write-scope enforcement. Keep independent history and legacy unscoped behavior compatible. An unexpected write into another owned stage still fails the study's write-scope check. Keep child-relative generation views and any finish that still owns unique proof. A registry rescan that covers the same root, lease, entries and receipts as the closing capture can use that comparison. Remove the duplicate published-generation finish and adoption reread only where the final check covers the same bytes, original scope, absence checks and receipts. Keep each generation receipt export scoped to its own inputs, including external pins, and exclude its own report as today. Do not build a multi-root reader or a stage-specific policy.

On a real mismatch, report the stage, category and bounded safe relative entry and changed fields where available. Preserve recorded spending and holds. Leave keys, raw content and arbitrary external paths out of diagnostics.

## Ask the same question again

| Proposed check | Wrong report that would otherwise get through |
| --- | --- |
| Original returned report pins | A child file differs from the result that guided the runner, or the study references a different screen publication from the one the screen runner returned. Either replacement could be valid by itself. |
| Exact membership and path kinds | An extra task, funded owner, completion seal or staged input is excluded, or a failed task is presented as having no later work when it does. |
| Sealed content and original bindings | The right names hide the wrong task, owner, answers, stage settings or score bytes. |
| Reconciled SQLite state | The report presents incomplete or differently funded work as settled. |
| Owned lock and final receipts and membership | The earlier checks were true, then a protected input or the right to publish changed. |
| Verified existing report or exclusive write | An older completion is overwritten, a different sealed result is accepted, or an incompatible accounting snapshot passes. |

No remaining check relies on directory clock values. A second read of the same input earns its place only when it closes a gap between first use and publication or before the next action makes a new decision.

## Smallest fallback

A directory-clock-only change through publication and the next study read would remove that veto with the least code. It would leave the post-loop child reread and the second preflight. Use it as the first cut if the binding checks cannot move without a new reader. Remove repetitions only as the focused proof shows the existing collector covers them.

## Short implementation proof

Reuse the supplied-worker screen and study fixtures. At the actual publication and next-action boundaries, directory timestamp or size drift should leave scores, provenance and spending unchanged and let the study advance. A harmless unconsumed regular-file metadata change outside the protected membership and the study's other owned stages should not veto publication. A canonical substituted child report with a compatible historical accounting snapshot must fail its original digest check. An otherwise compatible substituted screen report must also fail the immediate study read's returned-report pin. A whitespace-only change already fails canonical validation and cannot prove that protection. A protected byte change after first read, a late extra owner/seal/staged input, a lost lock or unstable ledger must stop with the report unwritten or the next action blocked, as applicable. Replacing a lock must leave the replacement alone. Use a scoped fixture for trial lease loss and retain the unscoped test.

Reuse the existing complete and terminal failure cases. Check a bare evaluation directory, an extra terminal seal, a later native owner missing its task binding, a changed external trial control after child return, a harmless post-settlement change to a dispatch-only input that remains subject to the next dispatch check, a compatible saved root report after unrelated grant progress, a noncanonical scoped root report, and a divergent saved root report. Compare census, receipt-pass and preflight counts at the real boundary. Confirm one pre-dispatch preflight, no separate child-report sweep, no repeated full execution validation during publication and no additional provider dispatch from publication or readback. A nested pass is removable only when the check also shows equal scope and rejection behavior. Use short checks with supplied inputs. They establish publication and handoff behavior, while a completed live comparison remains the scientific deliverable.

Two independent EGM Goldfish reviews challenged the draft against the code. The revision addresses original child pins, the preflight's unique checks, nested capture scope, lock replacement, external receipt stability, existing reports and the next study read. The follow-up review removed the remaining requirement to rehash dispatch-only files at publication. Runtime proof is pending.
